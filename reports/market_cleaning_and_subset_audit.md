# 市场底座清洗消融与非新工科子集实算审计报告

> 固定随机种子：`42` | 本次提交仅含清洗后的数据表、图表与审计报告（未包含脚本与业务代码）  
> 环境版本：Python `3.13.14` / pandas `3.0.3` / numpy `2.5.1` / scipy `1.18.0` / statsmodels `0.14.6`

## 一、核心结论（结果 → 证据 → 局限性 → 可执行启示）

1. **去重核验揭开两层重复**：59,430 条原始 JD 按 `job_url` 去重后精确等于申报书所写 **`57,416` 条**；但按规范化 `(job_name, company_name, city)` 跨类别/同企同城去重后仅剩 **`45,880` 条**（跨类别冲突 `10,180` 次，跨“非新工科/研发”边界冲突 `1,577` 次）。
2. **旧版子串 `in` 匹配存在显著假阳性污染**：L0 原始子串与 L2 干净口径之间整体排名 Spearman 相关系数仍高（$\rho = 0.9865$, $p = 6.57e-26$），但在高频与关键短英文别名上出现了系统性畸变——尤其是 **`ps`（误匹配 `deepseek` / `devops` / `ups` / `gps`）** 与 **`sd`（误匹配 `sdk` / `ssd` / `jesd204b`）** 让 `图文编辑` 被海量误算，**`less`（误匹配 `serverless` / `wireless`）** 和 **`rag`（误匹配 `storage` / `coverage`）** 同理；同时严格词边界会连带丢掉 `MySQL / PostgreSQL / Vue3 / vLLM / SDXL` 等真实技术变体（见下文显式变体对照）。
3. **旧版回归样本存在严重薪资截断偏置**：检查原始 CSV 发现，旧脚本 `parse_salary` 未解析 `万`（如 `1.8-2.8万`、`9千-1.1万`），把智联和前程无忧大量中高薪 `万` 口径样本直接丢弃，同时将 `学历不限 / 高中` 默认赋为 `本科(3)`，并将 `3年及以上 / 5年及以上 / 经验不限` 全部默认赋为 `1.0` 年。修复解析口径并加入 HC3 稳健标准误与 `log(salary)` 检验后，L2 干净全量有效月薪样本升至 **`41,667` 条**（`R² = 0.1454`）。
4. **非新工科真实子集与 Doc 11 方向一致但细节有边界**：L2 去重后窄口径（17 类，n=`7,719`，占 `16.82%`）与宽口径（21 类，n=`9,163`，占 `19.97%`）中，硕士占比分别仅 `1.84%` / `2.13%`（对照组研发岗 `8.94%`），`Python` 明确提及率分别仅 `5.01%` / `6.11%`（对照组 `27.82%`）；然而需如实指出：即便在非新工科子集内，**简单计数层面的软能力条数对月薪的 OLS 标准化回归系数仍接近 0 或略负**，说明“能力价值”不能靠统计字面技能条数简单线性拟合并声称数据拟合出 `45/40/15`。
5. **工程定位（持续防脏数据/防“有毒”数据门禁）**：上述去重、短词边界消融与多口径解析检查过程，均可直接综合进系统**每一次的数据导入与图谱更新流水线**中作为前置质检门禁，从源头阻断重复刷票、关键词假阳性和高薪截断偏差，避免图谱学到虚假相关性（“脏数据投毒”），确保数据底盘经得起评委复现与审稿查验。

## 五、局限性与诚实边界

1. **类别边界近似性**：基于 112 个 CSV 分类名切分的窄/宽口径能保证可复现性，但在同一招聘目录下（如 `数据治理`、`技术支持`）仍混有个别偏研发或纯售前岗位，这是抓取目录天然带有的颗粒度上限。
2. **基础月薪 vs N 薪**：统一抽取基本月薪中位数并去除 `·14薪` 后缀以保持横截面可比（避免年终奖估算猜测）；同时将日薪实习与时薪排除在正职月薪回归之外。
3. **为什么不能拿 OLS 系数倒推 45/40/15**：在任何子集中，影响市场起薪的主要观测解释力都来自**工作年限（经验）**与**学历门槛**，而招聘文本中出现的零散软能力词数量本身不决定高薪。因此，**市场大数据的正当作用是证明“非新工科岗位确实以本科和软能力协作为主导、学历门槛温和且硬技能分散”**，而 `45/40/15` 的真正有效性验证仍必须等待人类专家标注集落地后在排序/推荐任务上做实验 2（消融对照）。
