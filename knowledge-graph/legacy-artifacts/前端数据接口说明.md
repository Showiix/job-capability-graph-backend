# 前端数据接口说明

> 本文档面向前端同学，描述三个JSON文件的结构、字段含义和渲染建议。
> 所有数据由后端算法离线生成，前端直接 `import` 即可，无需调API。

---

## 文件总览

| 文件 | 大小 | 用途 | 渲染目标 |
|------|------|------|---------|
| `capability_update_report.json` | 7.9MB | 全量岗位时序数据 | **岗位详情页**：时间轴 + 变化卡片 |
| `capability_graph_updates.json` | 56KB | 图谱动态更新列表 | **图谱页**：节点状态标记、连边建议 |
| `calibrated_graph.json` | 474KB | 最终校准图谱 | **图谱页**：主视图渲染 |

> ⚠ 7.9MB 建议首屏只取索引（`reports[].job` + `reports[].change_summary`），点击岗位后再按需加载完整 `timeline` + `changes`。

## 一、capability_update_report.json

### 顶层结构

```json
{
  "generated_at": "2026-08-06T23:12:57",   // 生成时间（ISO格式）
  "total_jobs_analyzed": 760,                // 分析岗位总数
  "total_changes": 4007,                     // 变化总数
  "total_graph_updates": 4007,               // 图谱更新条目数
  "config": {                                // 算法参数（仅供了解）
    "window_size": 10,
    "step": 3
  },
  "summary": {                               // 快速统计
    "jobs_with_changes": 524,
    "jobs_without_changes": 236
  },
  "reports": [ ... ],                        // ← 核心数据，760个岗位
  "update_index": { ... },                   // 岗位名→更新摘要，用于搜索/列表
  "graph_updates": [ ... ]                   // 同 capability_graph_updates.json
}
```

### reports[i] — 单个岗位

```json
{
  "job": "算法工程师",
  "total_jds": 344,                    // 该岗位JD总数
  "dated_jds": 344,                    // 有日期的JD数
  "time_range": "1月6日 ~ 12月31日",    // 数据时间跨度
  "window_count": 112,                 // 滑动窗口个数 = timeline长度
  "window_size": 10,                   // 每窗口JD数
  "step": 3,                           // 窗口步长
  "timeline": [ ... ],                 // ← 时间轴数据
  "changes": [ ... ],                  // ← 检测到的变化列表
  "change_summary": "新增20项, 衰退15项, ...", // 一句话概述
  "update_summary": "该岗位新增AI技能：智能体、大模型..."  // 详细更新描述
}
```

### timeline[i] — 时间轴采样点

每个窗口是一个采样点，按时间顺序排列。前端渲染为**连续渐变的时间轴**。

```json
{
  "window_index": 0,                   // 窗口序号（0为最早）
  "date_range": "1月6日 ~ 3月10日",    // 该窗口覆盖的时间范围
  "jd_count": 10,                      // 窗口内JD数量
  "top_skills": [                      // 窗口内Top技能
    {
      "skill": "大模型",
      "effective_count": 4.0,          // 通胀校准后的有效出现次数
      "essential": 4.0,                // 作为"必备"出现的次数
      "bonus": 0.0                     // 作为"加分项"出现的次数
    },
    { "skill": "深度学习", "effective_count": 3.0, "essential": 3.0, "bonus": 0.0 },
    { "skill": "Python", "effective_count": 3.0, "essential": 1.0, "bonus": 2.0 }
  ]
}
```

**渲染建议：**
- X轴：`window_index` 或 `date_range`
- Y轴：某技能的 `effective_count` / `window_size` = 出现率
- 折线图/面积图，展示技能热度随时间变化
- 支持用户选择关注的技能画对比折线

---

### changes[i] — 检测到的变化

```json
{
  "skill": "智能体",
  "category": "AI技能新增",            // 变化类型，见下方分类表
  "confidence": "中",                   // 置信度：高 / 中
  "effect_size": 1.159,                 // Cohen's h 效应量（≥0.2=中等，≥0.5=大）
  "p_value": 0.2105,                    // Fisher精确检验 p值
  "statistically_significant": false,   // 是否通过统计显著性检验
  "early_prevalence": 0.0,              // 早期窗口出现率
  "late_prevalence": 0.3,               // 晚期窗口出现率（0.3 = 30%）
  "late_essential_count": 3.0,          // 晚期作为"必备"的次数
  "late_bonus_count": 0.0,              // 晚期作为"加分"的次数
  "skill_type": "AI新兴技能",           // 技能类别：AI新兴技能 / 传统技能
  "_from_window": 0,                    // 对比起始窗口索引
  "_to_window": 101,                    // 对比结束窗口索引
  "_from_date": "1月6日 ~ 3月10日",     // 起始窗口时间
  "_to_date": "7月30日 ~ 7月31日"       // 结束窗口时间
}
```

### 变化类型一览（共8类）

| category | 含义 | 前端渲染建议 |
|----------|------|-------------|
| `技能新增` | 前期几乎无，后期显著出现 | 🟢 绿色"新增"标签 |
| `AI技能新增` | 前期几乎无，后期AI技能显著出现 | 🔵 蓝色"AI新技能"标签（重点突出） |
| `技能衰退` | 前期常见，后期显著减少 | 🔴 红色"衰退"标签 |
| `技能权重上升` | 前后都有但出现率显著增长 | 🟠 橙色"↑权重上升" |
| `技能权重下降` | 前后都有但出现率显著降低 | 🟡 黄色"↓权重下降" |
| `升级（加分→必备）` | 从加分项变为必备要求 | ⬆️ "升级"箭头 |
| `降级（必备→加分）` | 从必备要求降为加分项 | ⬇️ "降级"箭头 |
| `过时技能淘汰` | 已知被淘汰的技术 | ❌ "淘汰"标签 |

### 置信度渲染建议

| confidence | 处理方式 |
|-----------|---------|
| `高` | 实线/实心/高亮，优先展示 |
| `中` | 虚线/半透明，折叠在"更多"里 |

## 二、capability_graph_updates.json

扁平列表，每条对应一个技能在某个岗位上的变化。用于图谱的动态状态标记。

```json
[
  {
    "job": "算法工程师",
    "skill": "智能体",
    "change_type": "AI技能新增",
    "confidence": "中",
    "effect_size": 1.159,
    "action": "suggest_edge"           // 建议的图谱操作
  },
  {
    "job": "算法工程师",
    "skill": "模型推理",
    "change_type": "AI技能新增",
    "confidence": "高",
    "effect_size": 0.982,
    "action": "add_edge"               // 高置信度→直接加边
  }
]
```

### action 含义

| action | 含义 | 前端处理 |
|--------|------|---------|
| `add_edge` | 高置信度新增/上升 → 建议添加图谱连边 | 实线边 |
| `suggest_edge` | 中置信度新增/上升 → 弱建议 | 虚线边 |
| `mark_deprecated` | 技能衰退/淘汰 → 标记节点 | 节点变灰 |
| `upgrade_weight` | 技能升级（加分→必备） | 节点边框加粗 |
| `downgrade_weight` | 技能降级（必备→加分） | 节点边框变细 |
| `no_action` | 无需操作 | 忽略 |

## 三、calibrated_graph.json

### 顶层结构

```json
{
  "calibrated_at": "2026-08-06T23:34:59",
  "pipeline": { ... },                  // 校准过程统计（前端一般不用）
  "graph": {                            // ← 图谱数据
    "nodes_count": 50,
    "edges_count": 200,
    "predicted_nodes": 0,
    "nodes": { ... },                   // 节点（以技能名为key的字典）
    "sample_edges": [ ... ],            // 边列表
    "stats": { ... },                   // 统计摘要
    "top_skills": [ ... ],              // Top技能排名
    "predicted_skills": [ ... ]         // 预测性新增技能
  }
}
```

### nodes — 节点字典

Key 是技能名（如 `"Python"`, `"大模型"`），Value 是节点属性：

```json
{
  "Python": {
    "effective_count": 5746.95,       // 通胀校准后的全平台有效出现次数
    "category": "传统技能",            // 传统技能 / AI新兴技能
    "status": "stable",               // stable / growing / emerging
    "dynamic_status": null,           // null / skill_emerging / skill_declining / skill_upgraded
    "is_inflated": false,             // 是否为通胀技能（抄袭导致虚高）
    "inflation_details": null,        // 通胀详情
    "change_history": [               // 关联的变化记录
      {
        "job": "算法工程师",
        "change_type": "技能权重上升",
        "confidence": "高",
        "effect_size": 1.339
      }
    ]
  }
}
```

### status 和 dynamic_status 的前端映射

| status | dynamic_status | 前端渲染 |
|--------|---------------|---------|
| `stable` | `null` | 默认圆形节点 |
| `stable` | `skill_emerging` | 默认节点 + 🟢"上升中"动画 |
| `stable` | `skill_declining` | 默认节点 + 🔴"衰退中"动画 |
| `stable` | `skill_upgraded` | 默认节点 + ⬆️"升级"标记 |
| `growing` | - | 虚线圈 + 脉冲动画 |
| `emerging` | - | 闪烁节点 + 新增提示 |

### sample_edges — 边列表

```json
{
  "source": "C++",
  "target": "Linux",
  "weight": 80,                        // 边权重（0-100），控制线条粗细
  "relation": "co_occurs"              // 关系类型：co_occurs = 共现
}
```

**渲染建议：**
- `weight` → 线条粗细（建议映射到 1px-8px）
- `relation: co_occurs` → 默认灰色连线
- 有 `dynamic_status` 的节点 → 高亮颜色（绿/红/蓝）

### stats — 图谱统计

```json
{
  "stable": 50,                        // 稳定技能数
  "growing": 0,                        // 增长中技能数
  "emerging": 0,                       // 新兴技能数
  "by_category": {
    "传统技能": 42,
    "AI新兴技能": 8
  },
  "inflated_skills": 5,                // 被通胀校准的技能数
  "dynamic": {
    "skill_emerging": 20,              // 动态上升中的技能数
    "skill_declining": 18,             // 动态衰退中的技能数
    "skill_upgraded": 1                // 动态升级的技能数
  }
}
```

可用作图谱页顶部的统计卡片（稳定50 / 增长0 / 新兴0 / 上升中20 / 衰退中18）。

## 四、前端渲染建议

### 岗位详情页

```
┌─────────────────────────────────────────────────┐
│  算法工程师                          344条JD     │
│  时间跨度：1月 ~ 12月                 112个采样点  │
├─────────────────────────────────────────────────┤
│                                                 │
│   [时间轴：技能热度折线图]                        │
│   4.0│         大模型 ╱╲                         │
│      │   深度学习 ╱    ╲___                      │
│   0.0│─────────────────────────                 │
│      窗口0 ──────────────────── 窗口111          │
│                                                 │
├─────────────────────────────────────────────────┤
│  技能变化（72项）                                │
│  ┌──────────┬────────┬────┬────────────┐        │
│  │ 🔵 AI新增 │ 智能体  │ 中 │ 从0→30% ↗ │        │
│  │ 🔵 AI新增 │ 大模型  │ 中 │ 从0→30% ↗ │        │
│  │ 🟢 新增   │ C++     │ 高 │ 从0→20% ↗ │        │
│  │ 🔴 衰退   │ 数据分析 │ 中 │ 80%→30% ↘ │        │
│  │ 🟠 权重↑  │ Python  │ 高 │ 60%→90% ↗ │        │
│  └──────────┴────────┴────┴────────────┘        │
└─────────────────────────────────────────────────┘
```

### 图谱页

```
统计卡片：[节点50] [边200] [稳定50] [上升中20] [衰退中18] [升级1]

[力导向图 / ECharts Graph]

  节点渲染：
  - 大小=effective_count的对数
  - 颜色=category（AI蓝/传统灰）
  - 有dynamic_status的节点→脉冲动画
  - is_inflated=true的节点→虚线边框

  连线：
  - weight→线条粗细
  - co_occurs→灰色线

  交互：
  - 点击节点→弹出change_history列表
  - 切换显示层：全部/仅AI/仅动态/仅通胀
```

## 五、性能优化建议

| 问题 | 建议 |
|------|------|
| 7.9MB 太大 | 首屏只取 `reports[].job` + `reports[].change_summary` 渲染列表，点击岗位后懒加载 |
| gzip 压缩 | 服务器开启 gzip，7.9MB → ~1MB |
| 时间轴数据量 | 单个岗位最多112个采样点，ECharts 轻松渲染 |
| 图谱交互 | 50节点200边，d3.js/vis.js/ECharts 都能流畅跑 |
